# GeoView Terminology

This glossary defines terms used across GeoView's developer documentation and source code. For details, follow the links to the relevant architecture guides.

| Term                                               | Meaning                                                                                                                                                                                                                                                                                   |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Package**                                        | A separately maintained and built unit in the GeoView Rush monorepo. `geoview-core` provides the foundation; plugin packages extend it and should use its supported APIs rather than depend on another package's private implementation details.                                          |
| **Plugin package**                                 | A package that extends or integrates with `geoview-core`, such as `geoview-swiper` or `geoview-time-slider`. Plugin packages consume core APIs; core does not depend on plugin implementation details.                                                                                    |
| **Map configuration**                              | The declarative configuration for a map, including its view, basemap, layers, UI components, and package settings. It is distinct from state that changes while the map is running. See the [configuration reference](../app/config/configuration-reference.md).                          |
| **GeoView layer configuration**                    | The declarative configuration for a service or layer that GeoView validates and uses to create a GeoView layer. It can contain one or more layer entry configurations.                                                                                                                    |
| **Layer entry configuration**                      | The configuration for an individual layer-tree entry, including its source, initial settings, and—when it is a group—child entries.                                                                                                                                                       |
| **GeoView layer**                                  | A core layer object responsible for its configuration and lifecycle, including metadata validation and creating its runtime GV layers. A GeoView layer is not the same thing as its configuration object or an OpenLayers layer.                                                          |
| **GV layer**                                       | GeoView's runtime wrapper around an OpenLayers layer. GV layers provide GeoView-specific rendering, querying, and interaction behavior. See the [layers guide](../app/layers/layers.md).                                                                                                  |
| **Layer state**                                    | Runtime state associated with a layer and used by GeoView's UI and application logic, such as visibility, opacity, selection, or item visibility. It is distinct from the layer's declarative configuration.                                                                              |
| **Layer set**                                      | A reactive collection that tracks layers and derived information for a particular purpose, such as legends, details, or feature queries. See [LayerSet Architecture](./layerset-architecture.md) and the [Layer Sets guide](../app/layers/layersets.md).                                  |
| **MapViewer**                                      | The GeoView runtime object that coordinates a map instance, its OpenLayers map, configuration, layers, and controllers. React components should interact through controllers rather than receive or access the `MapViewer` directly.                                                      |
| **Map element**                                    | The DOM element that hosts the OpenLayers map viewport. It is distinct from the outer GeoView viewer shell, which also contains controls and panels.                                                                                                                                      |
| **Extent**                                         | An axis-aligned bounding box represented as `[minX, minY, maxX, maxY]` in a coordinate reference system. An extent is not inherently longitude/latitude; its coordinate system must be known when transforming or displaying it.                                                          |
| **Projection / coordinate reference system (CRS)** | The spatial reference used to interpret coordinates and extents. GeoView maps and layer data may use different projections, so coordinates must be transformed when moving between them.                                                                                                  |
| **Controller**                                     | The application-level interface for business logic and side effects, such as changing map zoom or layer visibility. UI components call controllers instead of manipulating `MapViewer`, OpenLayers, or store state directly. See [Controller Architecture](./controller-architecture.md). |
| **Domain**                                         | A backend model that owns runtime objects and emits domain events. Controllers subscribe to those events and synchronize application state. See [Controller Architecture](./controller-architecture.md).                                                                                  |
| **Store state**                                    | Reactive application state exposed through GeoView's Zustand store. Components read it through selectors and request changes through controllers.                                                                                                                                         |
| **Scoped instruction**                             | An AI guidance file that applies automatically to matching files, based on its `applyTo` pattern.                                                                                                                                                                                         |
| **AI reference**                                   | An on-demand `.github/ai/*.md` document containing detailed, focused project patterns and lessons for AI agents. It complements public developer documentation rather than replacing it.                                                                                                  |
| **Workflow agent**                                 | A custom AI agent designed to complete a defined end-to-end task, such as a branch review or test authoring workflow.                                                                                                                                                                     |
| **Specialist agent**                               | A custom AI agent focused on a domain and commonly delegated to by the main agent for a bounded task.                                                                                                                                                                                     |
| **Architecture adviser**                           | A specialist role that evaluates system-wide design, package dependencies, and trade-offs, then recommends an approach without implementing it. In this repository, `GeoViewArchitect` has this role.                                                                                     |

When a term is ambiguous in a particular subsystem, prefer that subsystem's architecture documentation and source types over inferring behavior from the glossary alone.
